# حوكمة تحويل الصور المرجعية إلى رحلات واجهة

## 1. الغرض والحدود

هذه الوثيقة هي الهيكل الإلزامي لأي صورة واجهة يرسلها مالك المنتج مستقبلاً. الصورة **مرجع للهيكل، والتسلسل، والكثافة البصرية** وليست أمراً بالنسخ الحرفي ولا تفويضاً تلقائياً لقدرات جديدة. لا يبدأ تعديل الواجهة قبل إصدار تقرير تحليل واعتماده.

لا تجيز هذه الوثيقة إنشاء دفع أو حجز أو طلبات أو إشعارات أو تقييمات أو أسعار أو ضمانات أو أي قدرة مستقبلية. كل عنصر يحتاج مساراً قانونياً، وحالة بيانات، وعقد API معتمداً؛ وإلا يحذف أو يوسم بوضوح كعنصر غير تفاعلي/مستقبلي.

## 2. دورة العمل الإلزامية لكل صورة

### المرحلة A — التحليل قبل التنفيذ

يصدر تقرير يحمل `IMG-<رقم>` ويتضمن بالترتيب:

1. **تحليل الصورة:** الهدف، نوع الصفحة، ترتيب الكتل، الأفعال الأساسية والثانوية، حالات البيانات، والهوية البصرية.
2. **القابلية للتطبيق:** لكل عنصر قرار `يطبق` أو `يعدل` أو `يحذف` أو `يؤجل` مع السبب ومرجع نطاق V1.
3. **خريطة الحقن:** الصفحة/المكوّن/المسار/API/الصلاحية/حالة التحميل والخطأ والفراغ لكل فعل.
4. **جرد الأزرار والأيقونات:** النص أو `aria-label`، الوجهة أو المعالج، أثر الضغط، شرط الصلاحية، وحالة الاختبار.
5. **تقييم التصميم من 10:** وضوح 2، اتساق 2، قابلية استخدام 2، وصول 2، وملاءمة نطاق 2.
6. **اقتراح التنظيف:** ما يحذف لتقليل العشوائية والتكرار وما يبقى كهوية.

النتيجة تكون واحدة فقط: `GO` أو `REPAIR BEFORE IMPLEMENTATION` أو `DEFER` أو `REJECT`.

### المرحلة B — اعتماد رحلة المستخدم

قبل الكود، تربط الصورة بما قبلها وما بعدها في جدول واحد:

| الحقل | المطلوب |
| --- | --- |
| نقطة الدخول | الصفحة والفعل اللذان أوصلا المستخدم |
| الإجراء الأساسي | فعل واحد واضح فقط |
| نتيجة النجاح | مسار قانوني وحالة مستخدم محددة |
| الإلغاء/الرجوع | وجهة لا تفقد بيانات المستخدم دون تحذير |
| الفشل | رسالة عربية، retry آمن، وعدم الادعاء بالنجاح |
| عدم المصادقة/الصلاحية | redirect أو منع موثق |
| التالي | الصورة التالية أو نهاية الرحلة |

لا تعتمد صورة منفردة إذا صنعت طريقاً مسدوداً أو كررت صفحة قانونية موجودة.

### المرحلة C — التنفيذ والحقن

- تستخدم مكونات وهوية المنصة، ولا تنسخ الصورة pixel-for-pixel.
- كل زر مرئي يجب أن يكون `button` بفعل حقيقي أو `Link` إلى مسار موجود.
- الأيقونة الزخرفية غير قابلة للنقر و`aria-hidden`؛ الأيقونة الفعالة داخل هدف نقر لا يقل عن 44×44px ولها اسم وصول.
- يمنع السعر أو «الأكثر طلباً» أو «مضمون» دون مصدر بيانات وعقد معتمد.
- يمنع إخفاء نتيجة API بصرياً مع إبقاء طلب الشبكة؛ إما تعرض البيانات بأمان أو لا يرسل الطلب.
- حالات loading/error/empty/disabled/focus جزء من التنفيذ وليست تحسيناً لاحقاً.

### المرحلة D — الفحص بعد الحقن

يصدر تقرير مقارنة بعد التنفيذ يتضمن:

1. لقطة للمرجع ولقطات runtime على 360px و768px و1440px.
2. جدول `مطلوب/منجز/جزئي/غير مطبق/محذوف عمداً` لكل عنصر.
3. فحص كل زر بلوحة المفاتيح واللمس، والوجهة، والعودة، والصلاحية، وفشل الشبكة.
4. فحص كل أيقونة: SVG موحد، الاسم، الحجم، التباين، الهدف، وعدم وجود رمز بلا وظيفة.
5. فحص RTL، قارئ الشاشة، focus، reduced motion، overflow، و44×44px.
6. فحص API والبيانات: payload، الاستجابة، loading/error/empty، ومنع الادعاءات الوهمية.
7. إعادة التقييم من 10 مع الفرق عن تقييم ما قبل التنفيذ.

لا يقال «مطبق بالكامل» إذا كان زر واحد بلا أثر، أو مسار يؤدي إلى 404، أو بيانات العرض ثابتة بينما توحي بأنها حية.

## 3. سجل اختبار الأزرار

يسجل كل عنصر بالصيغة التالية:

| ID | الصورة/الصفحة | العنصر | النوع | الوجهة/المعالج | الاعتماد الداخلي | اختبار success | اختبار failure | وصول | القرار |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| مثال | IMG-X | متابعة | Link | `/next` | route موجود | انتقال صحيح | لا ينطبق | اسم وتركيز | يعمل |

حالات القرار المسموحة: `يعمل`، `يعمل جزئياً`، `لا يعمل`، `غير محقون`، `محذوف عمداً`.

## 4. ترتيب رحلة «الخدمة المركزية» المعتمد

عند اختيار خدمة مركزية، لا تنفذ صور عشوائية؛ توضع الصور في رحلة مكتملة:

1. **الدخول:** تسجيل الدخول أو إنشاء الحساب عند الحاجة فقط.
2. **تهيئة أول مرة:** شاشة ترحيب قصيرة يمكن تجاوزها ولا تتكرر كل زيارة.
3. **الرئيسية:** بحث وفئات وخيار أساسي واحد.
4. **فئة الخدمة:** عنوان الفئة وفلترة ونتائج حقيقية.
5. **نتيجة/مقدم خدمة:** تفاصيل حقيقية وملف مقدم الخدمة.
6. **التواصل المعتمد:** قناة التواصل الحالية فقط؛ لا حجز أو دفع أو طلبات ما لم تعتمد كقدرات مستقلة.
7. **نهاية واضحة:** نجاح التواصل أو عودة آمنة إلى النتائج.

أي صورة مستقبلية توضع في موضع واحد من هذه الرحلة قبل تحليلها، ويمنع القفز من الفئة إلى «طلباتي» إذا لم توجد قدرة طلب قانونية.

## 5. المسؤولية والقبول

- المساعد مسؤول عن التحليل، كشف العناصر الميتة، اقتراح الحذف، الاختبارات، والتقرير الصريح.
- مالك المنتج يعتمد `GO` أو يطلب إصلاح التقرير.
- التنفيذ مهمة لاحقة منفصلة؛ لا يعد تقييم الصورة تفويضاً بتوسيع V1.
- درجة 8/10 لا تعني الجاهزية إذا فشلت بوابة نطاق أو بيانات أو وصول؛ البوابات الحرجة تتقدم على الدرجة.
