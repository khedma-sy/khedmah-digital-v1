# التقرير الهندسي والتصميمي لنظام التفاعل — خدمة ديجتل

## القرار التنفيذي

يعتمد هذا التقرير الصورتين المرفقتين في مهمة 2026-08-08 **مرجعاً اتجاهياً** للمظلة الرقمية، خريطة سوريا، اللون الأزرق، بطاقات الأيقونات، وتوزيع عناصر الموبايل. لا تعد الصور مواصفات تنفيذ حرفية، ولا تمنح تفويضاً للـMarketplace أو الدفع أو الرسائل أو التسويق أو الذكاء الاصطناعي.

القرار: **واجهة أقل، أفعال أوضح، ولا زر بلا قدرة معتمدة وحالة كاملة وقياس آمن.**

يرتبط هذا التقرير بـ[الهيكل التنظيمي للمنصة](../product/LIVE-PLATFORM-INFORMATION-ARCHITECTURE.md) و[نطاق V1](../product/V1-SCOPE.md).

## 1. منهج EXPASE / AUTOPOSE / IQ / KILLCRITIC

يخضع كل زر أو أيقونة تفاعلية لأربعة اختبارات:

1. **EXPASE — Exposure:** ما البيانات أو الصلاحية التي يكشفها الفعل؟
2. **AUTOPOSE — State:** هل حالات idle وhover وfocus وloading وsuccess وerror وdisabled موثقة؟
3. **IQ — Intent Quality:** هل يستطيع المستخدم توقع النتيجة قبل الضغط؟
4. **KILLCRITIC — Scope:** هل القدرة معتمدة وقابلة للاختبار الآن؟

يُحذف العنصر إذا تكرر هدفه، أو لم يملك مساراً صالحاً، أو أوحى بميزة غير موجودة. ويؤجل إذا كانت الفكرة صحيحة لكن القدرة خارج V1.

## 2. تشريح المرجع البصري

### عناصر تُعتمد

- خلفية كحلية عميقة مع أزرق كهربائي محدود.
- علامة واضحة في ركن ثابت دون تكرارها داخل كل كتلة.
- مظلة رقمية كعنصر هوية، لا كزر.
- خريطة سوريا كمدخل بصري للموقع عند تفويض تجربة المواقع.
- بطاقات أيقونات متساوية، عنوان قصير، ومساحة لمس لا تقل عن 44px.
- شريط موبايل سفلي بخمسة مواضع كحد أقصى **فقط عندما تصبح قدراته الخمس معتمدة**.
- مشاركة أصلية من نظام التشغيل عند توافر رابط عام فعلي.

### عناصر لا تُنسخ

- ازدحام عشرات الأيقونات في شاشة واحدة.
- glow قوي يخفض تباين النص.
- استخدام صور المرجع كواجهة فعلية أو كبديل لعناصر HTML القابلة للوصول.
- زر طلب خدمة عائم قبل اعتماد دورة طلب الخدمة.
- محفظة ورسائل وتقييمات وإشعارات قبل وجود عقودها وصلاحياتها.
- أرقام زيارات أو تسجيلات أو عوائد غير صادرة عن مصدر بيانات معتمد.

الرئيسية، البحث، حسابي، ملفاتي، ومؤسساتي روابط دلالية `<a>` وليست `<button>`. لا تُصمم كخمسة أزرار CTA متنافسة.

### 3.3 أزرار تُحذف من الواجهة العامة الحالية

| العنصر | سبب الحذف |

| أزرار Premium وBusiness | توحي بشراء غير متاح في V1 |

## 4. بنية شريط التنقل

### الضيف — سطح المكتب

```text
[KD + KHEDMA DIGITAL]  الرئيسية  البحث  [دخول] [إنشاء حساب]
```

لا تظهر «أعمالي»، «منظماتي»، أو اسم مستخدم للضيف. المحافظات والخدمات تدخل من البحث أو محتوى الرئيسية، لا تكرر في موضعين.

### المستخدم المسجل — سطح المكتب

```text
[KD + KHEDMA DIGITAL]  الرئيسية  البحث  أعمالي  منظماتي  [اسم المستخدم] [خروج]
```

### الموبايل في V1

Header مصغر + قائمة وصول واضحة. لا يعتمد الشريط الخماسي المصور قبل اعتماد طلب الخدمة والرسائل والإشعارات. عند اعتماده مستقبلاً يكون: الرئيسية، البحث، الإجراء المعتمد، النشاط، الحساب.

## 5. مواصفة مكوّن الزر

### الأنواع

- **Primary:** إجراء واحد فقط لكل كتلة؛ خلفية Electric 500.
- **Secondary:** بديل حقيقي؛ سطح شفاف وحد واضح.
- **Tertiary:** فعل منخفض الأولوية داخل المحتوى.
- **Icon button:** فعل مفهوم عالمياً مع tooltip و`aria-label`.
- **Destructive:** حذف/إلغاء دائم؛ لا يستخدم للعودة أو الخروج العادي.

### الحالات الإلزامية

| الحالة | السلوك |
| --- | --- |
| Default | نص وفعل واضحان |
| Hover | تغير لون أو ارتفاع لا يتجاوز 2px |
| Focus visible | حلقة تركيز 3px لا تعتمد على اللون وحده |
| Pressed | scale لا يقل عن 0.96 ودون تغيير التخطيط |
| Loading | يبقى العرض ثابتاً ويمنع التكرار |
| Success | رسالة قرب موضع الفعل، لا لون فقط |
| Error | سبب آمن وخطوة تصحيح |
| Disabled | سبب التعطيل ظاهر عند الحاجة |

### القياس

يسجل الحد الأدنى اللازم فقط: `eventName`, `surface`, `actionId`, `result`, `timestamp`, ومرجع جلسة غير كاشف. يمنع وضع الاسم أو البريد أو العنوان أو نص الرسالة أو الموقع الدقيق في analytics.

## 6. مواصفة الأيقونات والحركة

- مصدر SVG واحد وسمك stroke موحد.
- يمنع emoji وUnicode كأيقونات إنتاجية.
- لون افتراضي واحد؛ اللون الدلالي للحالة فقط.
- الأيقونة المرفقة بنص ليست تفاعلية مستقلة.
- hover: ارتفاع 2–4px خلال 160ms.
- press: scale إلى 0.96 خلال 100ms.
- يمنع الدوران المستمر والنبض العام؛ النبض محجوز للحالة الحية الحقيقية.
- جميع الحركات تتوقف مع `prefers-reduced-motion`.

## 7. المشاركة الآمنة

المشاركة مسموحة فقط لصفحة منشورة وعامة. الحمولة:

- الاسم العام المعتمد.
- وصف قصير من الحقول العامة.
- صورة عامة معتمدة.
- canonical URL.

تستخدم Web Share API عند توافرها، مع fallback لنسخ الرابط. لا يُنشأ تكامل خاص بواتساب أو فيسبوك أو إنستغرام في V1، ولا تُرسل بيانات المستخدم لتلك الجهات تلقائياً. QR مؤجل حتى اعتماد canonical public URLs.

## 8. الصفحة الرئيسية المنقحة

```text
Header
Hero: عنوان + وصف + بحث + CTA واحد
مرجع المظلة والخريطة (عرض/دخول موقع بحسب التفويض)
كيف تعمل المنصة: اكتشف، تحقق، تواصل
أنواع الحضور المعتمدة
الثقة والخصوصية
CTA إنشاء حساب واحد
Footer
```

يحذف من الصفحة: الخطط المدفوعة، محاكاة ملف تسويقي وهمي، أرقام غير موثقة، وأي زر يكرر التسجيل أو البحث.

## 9. البنية الهندسية المسموحة

### وحدات V1 التنفيذية

Identity، Users، Organizations، Contact، Analytics allowlist، والحد الأدنى المعتمد من الملفات العامة.

### وحدات reserved فقط

Services المتقدم، Marketplace، Marketing، Payments، Notifications، Messaging، Referrals، AI، والتصنيف الذكي. لا تُنشأ APIs لها لمجرد وجودها في صورة أو رؤية مستقبلية.

### قواعد API

- لا endpoint بلا عقد طلب/استجابة وأخطاء وصلاحيات واختبارات.
- لا API مستقل لكل زر؛ الزر يستهلك قدرة تطبيق معتمدة.
- لا Feature Flag يحول ميزة غير معتمدة إلى ميزة قانونية.
- Feature flags تفصل الإطلاق فقط بعد اكتمال الحوكمة والتنفيذ.

## 10. اللوجستيات والموقع

التسلسل المرجعي: دولة ← محافظة ← مدينة/منطقة. لا يجمع GPS تلقائياً، ولا ينشر وجود مستخدم جديد في مدينة. اختيار المحافظة أثناء onboarding يستخدم لتخصيص خاص بالمستخدم ما لم يوافق صراحة على نشر موقع عام ضمن ملف منشور.

## 11. لوحة الإدارة

تبقى الإدارة منفصلة عن الواجهة العامة. V1 يعرض فقط القدرات المرتبطة بصلاحية قائمة وبيانات حقيقية. Heat map، العوائد، الحملات، ورسوم النمو لا تظهر قبل اعتماد مصادرها وسياسة الخصوصية.

## 12. خطة الحذف والتوحيد

### P0 — قبل أي تحسين بصري

1. جرد كل `<button>` وCTA وربطه بمعرّف من السجل.
2. حذف الروابط المخفية والأفعال المكررة والأزرار المؤدية لصفحات مؤجلة.
3. فصل تنقل الضيف عن المسجل والإدارة.
4. إزالة الخطط المدفوعة والتسويق الوهمي من الصفحة العامة.

### P1 — النظام الموحد

1. إنشاء Button وIconButton وNavLink من design tokens واحدة.
2. استبدال emoji/Unicode بأصول SVG معتمدة.
3. توحيد loading/error/success وfocus وreduced motion.
4. اختبار 360px و768px و1440px.

### P2 — قدرات مستقبلية بعد الحوكمة

المشاركة العامة، QR، طلب الخدمة، الرسائل، الإشعارات، التسويق، الدفع، AI، وMarketplace كل منها يحتاج قراراً وعقداً وبوابة مستقلة.

## 13. معايير القبول

- CTA أساسي واحد لكل كتلة.
- لا زر ميت أو مخفي أو يكرر رابطاً آخر.
- لا عنصر يوحي بقدرة مؤجلة.
- لا emoji ضمن نظام الأيقونات الإنتاجي.
- 100% من الأزرار قابلة للوصول بلوحة المفاتيح ولها focus ظاهر.
- جميع الحالات والحركات تدعم reduced motion.
- كل حدث تحليلي allowlisted وخالٍ من البيانات الخاصة.
- مراجعة بصرية مقارنة بالمرجع على سطح المكتب والموبايل.
- نجاح اختبارات الواجهة والنطاق والأمان قبل الدمج.

## 14. الخلاصة

التميز لا يأتي من زيادة عدد الأزرار، بل من إزالة كل فعل غير ضروري وربط الباقي بقدرة موثوقة. المظلة والخريطة واللون الأزرق هي لغة الهوية؛ أما المحفظة والرسائل والتسويق وMarketplace والذكاء الاصطناعي فهي مسارات مستقلة لا تدخل V1 عبر التصميم.
