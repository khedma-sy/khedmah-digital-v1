## الأخطاء والعوائق المحفوظة

### MERGE-01 — غياب اتصال المستودع البعيد

- **الملاحظة:** نسخة العمل تحتوي على الفرع المحلي `work` دون `origin` أو فرع تتبع بعيد.
- **الأثر:** لا يمكن دفع الالتزامات أو تحديث طلب السحب أو إثبات الدمج من هذه النسخة.
- **المعالجة المطلوبة:** إضافة المستودع البعيد في بيئة مصادق عليها، جلب الفرع الافتراضي، ثم دفع الالتزامات إلى فرع طلب السحب المعتمد.
- **معيار الإغلاق:** ظهور الالتزام الأخير في طلب السحب وفي سجل GitHub البعيد.

### MERGE-02 — غياب مصادقة GitHub

- **الملاحظة:** أداة GitHub CLI متاحة، لكن لا توجد جلسة دخول أو صلاحية دفع في بيئة التنفيذ.
- **الأثر:** تعذر إنشاء طلب سحب أو تحديثه أو دمجه آلياً.
- **المعالجة المطلوبة:** تنفيذ المصادقة خارج المستودع باستخدام آلية الفريق الآمنة، دون حفظ رموز أو بيانات اعتماد داخل الملفات.
- **معيار الإغلاق:** نجاح قراءة طلب السحب ودفع فرعه من البيئة المعتمدة.

### CI-01 — إعادة التحقق من فحص الأمان بعد الدفع

- **الملاحظة:** تم تحديث `nanoid` من `3.3.16` إلى `3.3.18` في ملف القفل، ونجح `npm audit --omit=dev --audit-level=high` محلياً دون ثغرات.
- **الأثر المتبقي:** النتيجة لا تصبح دليلاً لطلب السحب حتى يُدفع الالتزام ويعيد GitHub Actions تشغيل الفحص.
- **المعالجة المطلوبة:** إعادة تشغيل `Run Tests & Verification` و`PR Preview / quality-gates` على الالتزام المدفوع.
- **معيار الإغلاق:** نجاح فحصي GitHub دون تجاوز أو تعطيل لبوابة الأمان.

### CI-02 — اختبارات الخلفية المعتمدة على PostgreSQL

- **الملاحظة:** التشغيل المحلي دون PostgreSQL أعاد `ECONNREFUSED` على `127.0.0.1:5432` لاختبارات الخلفية؛ نجحت اختبارات المستودع الأساسية واختبارات الواجهة.
- **التصنيف:** قيد بيئي محلي، وليس دليلاً حالياً على عيب في منطق الخلفية.
- **المعالجة المطلوبة:** تشغيل الحزمة الكاملة في بوابة CI التي توفر خدمة PostgreSQL، أو في بيئة محلية مماثلة قبل الدمج.
- **معيار الإغلاق:** نجاح `npm run test:all` كاملاً مع PostgreSQL.

### REVIEW-01 — دليل المعاينة البصرية

- **الملاحظة:** لم يُلتقط دليل بصري محلي لأن تنزيل متصفح Playwright كان محجوباً في بيئة التنفيذ السابقة.
- **الأثر:** لم تتم مقارنة واجهة ما قبل/بعد آلياً من النسخة المحلية.
- **المعالجة المطلوبة:** تفعيل `deploy-preview` ثم `review-evidence` بعد نجاح بوابات الجودة، ومراجعة RTL والخريطة والموبايل.
- **معيار الإغلاق:** توفر رابط معاينة وأدلة قبل/بعد وموافقة المالك.

## بوابة الدمج التالية

لا يغلق هذا السجل إلا بعد تحقق البنود التالية:

1. جلب أحدث فرع افتراضي ومعالجة أي تعارضات دون فقد التزامات المنصة الحية.
2. دفع الالتزامات الثلاثة إلى فرع طلب سحب معتمد.
3. نجاح البناء، الاختبارات الكاملة، فحص النوع، وفحص الأمان.
4. نجاح فحوصات Firebase وGoogle Cloud وعقود preview/staging.
5. توفر معاينة قابلة للمراجعة والتحقق من العربية RTL والاستجابة للموبايل.
6. دمج طلب السحب فعلياً والتحقق من وجود الالتزام الناتج في الفرع الافتراضي.
