# تقرير برنامج الإصلاحات الجوهرية الشامل

**مقدم إلى:** مجلس إدارة Khedmah Digital V1  
**تاريخ خط الأساس:** 2026-07-27  
**الفرع الذي جرى تقييمه:** `work`  
**نوع المهمة:** مراجعة واستقرار وحوكمة؛ لا تتضمن توسيع نطاق المنتج.

## 1. قرار تنفيذي مختصر

حالة المستودع الحالية **مستقرة وظيفياً في بيئة التحقق المحلية، لكنها غير جاهزة للإنتاج**. نجح التثبيت النظيف والبناء وجميع الاختبارات، إلا أن تدقيق التبعيات يسجل عقدة حرجة مباشرة في Next.js، وست عقد عالية، وعقدتين متوسطتين. كما أن وثيقة النطاق الرسمية ما زالت تصف V1 كمرحلة تأسيس توثيقية فقط، بينما يحتوي المستودع فعلياً على تطبيقات ومسارات وقواعد ترحيل؛ ولذلك لا يمكن اعتماد قائمة MVP نهائية أو إعلان الجاهزية للإنتاج قبل قرار إداري يصالح وثائق الحوكمة مع الواقع المنفذ.

**نسبة الجاهزية الحالية المقدرة: 63%.** هذه نسبة جاهزية هندسية نحو خط أساس MVP مرشح، وليست نسبة إنجاز تجاري أو وعد إطلاق. بنيت النسبة على المصفوفة والأوزان المعلنة في القسم 4، ولا تشمل أي وحدات مستقبلية أو محجوزة.

## 2. منهج المراجعة وحدودها

اعتمد التقييم على:

- قراءة وثائق النطاق والمنتج والعمارة والعقود والتشغيل والوحدات المحجوزة.
- جرد ملفات وحدات الخلفية والواجهة وقواعد البيانات والاختبارات ومسارات CI.
- تثبيت نظيف بواسطة `npm ci`، ثم بناء مساحات العمل وتشغيل الاختبارات القانونية الكاملة.
- تدقيق `npm audit --json` وفحص الإصدارات المتاحة بواسطة `npm outdated --json`.
- فحص ساكن لمسارات الصور، Server Actions، middleware، رفع الملفات، التخزين المؤقت، الحلقات والمسارات ذات الكلفة المحتملة.
- قياس زمني محلي واحد للبناء والاختبارات؛ هذا القياس **خط أساس أولي وليس اختبار حمل إنتاجياً**.

لم تجر مزامنة مع مستودع مركزي لأن النسخة المحلية لا تحتوي على `remote`. ولم تجر اختبارات اختراق، أو حمل، أو قاعدة بيانات حقيقية، أو متصفح طرفي، أو بيئة staging. لذلك تبقى أي استنتاجات أداء أو تعرض أمني خارج هذه الحدود تقديرية ومعلنة على هذا الأساس.

## 3. الإنجازات منذ التقرير السابق

1. أصبح `package-lock.json` متوافقاً مع مساحتي العمل، ونجح `npm ci` من حالة نظيفة.
2. أصلح عائق بناء NestJS الخاص باستجابة HTTP 429.
3. أضيفت تبعيات التحقق المطلوبة فعلياً لتشغيل `ValidationPipe`.
4. استعيد نجاح مسار الصحة في الاختبارات بتثبيت حقن الخدمة صراحة.
5. أصلح اختبار واجهة التسجيل الذي كان يفشل بسبب تعبير نمطي غير صحيح.
6. أصبحت بوابة الاستقرار الحالية ناجحة: بناء الخلفية والواجهة، و467 اختباراً ناجحاً (441 جذرياً، 20 للخلفية، و6 للواجهة).
7. استبدلت هذه المراجعة ادعاء «جاهز للإنتاج» السابق بتقييم قابل للتدقيق يفصل الاستقرار المحلي عن الجاهزية الأمنية والتشغيلية.
8. أنشئ سجل مخاطر وخطة معالجة أمنية وأداء وجودة دون تطبيق ترقيات قسرية أو إضافة خصائص.

### 4.2 الثقة في النسبة

الثقة **متوسطة** لأن البناء والاختبارات قابلان للتكرار محلياً، لكن لا توجد بيئة مركزية متصلة أو قاعدة بيانات تشغيلية أو معايير قبول تجارية مصادق عليها. يجب إعادة حساب المؤشر بعد قرار النطاق، لأن تغيير تعريف MVP يغير المقام نفسه.

### 5.2 الوحدات القانونية الموثقة غير المنفذة كمنتج

الوحدات التالية تملك عقوداً واختبارات حوكمة في `backend/modules` أو `backend/operations`، لكنها ليست كلها وحدات NestJS تشغيلية في `apps/backend`. لذلك تسجل كـ **تأسيس/عقد مكتمل جزئياً** وليس كميزة MVP مكتملة:

- Profiles وProfessional Profiles وBusiness Profiles.
- Locations وService Catalog وRelationships وTrust Verification.
- Business Case وOperational Status وApproval وPublication وVisibility.
- Public Business Profile وPublic Discovery وBusiness Search.
- Canonical Adapters وGovernance Resolution وAuthority Transport.

أي تحويل لها إلى API أو شاشة أو تخزين جديد هو توسيع تنفيذ ويحتاج مهمة منفصلة بعد اعتماد النطاق.

### 5.3 مؤجل ومحجوز خارج MVP

- `Khedmah Connect` اتجاه شبكة/منظومة مستقبلية.
- `أنا مع خدمة` تعبير علامة/مجتمع مستقبلي يجب الحفاظ عليه دون تنفيذه في هذه الدورة.
- Marketplace والمدفوعات والعمولات والطلبات والمخزون والإعلانات والترتيب المدفوع.
- Job Work كتدفقات تنفيذية، شبكة الشركاء والممثلين، Khedmah Sharing كشبكة اجتماعية، وذكاء السوق المتقدم.
- أي تتبع فردي، بيع بيانات، تكاملات قطاعية، أو بنية إنتاجية جديدة غير معتمدة.

## 7. المحور الثالث — الأمن

### 7.1 ملخص التدقيق

سجل `npm audit --json` تسع عقد حزم متأثرة: **1 حرجة، 6 عالية، 2 متوسطة** من أصل 214 تبعية كلية يحصيها npm. الحزم المباشرة المتأثرة هي `next` و`@nestjs/common` و`@nestjs/core` و`@nestjs/platform-express`. والعقد الانتقالية هي `file-type` و`multer` و`path-to-regexp` و`postcss` و`sharp`.

> العدد أعلاه عدد عقد الحزم الذي يقدمه npm، وليس عدد كل GHSA المجمعة داخل كل عقدة. ولا يعني انخفاض التعرض الحالي أن التنبيه مغلق.

### 7.3 خطة معالجة تدريجية

1. **دفعة A — P0 / موافقة الإدارة:** فرع ترقية أمني فقط لـ Next ضمن 15.x وReact/React DOM المتوافقين، دون انتقال إلى Next 16. يشغل التثبيت والبناء و467 اختباراً، ثم فحص smoke لمسارات الواجهة.
2. **دفعة B — P0:** ترقية حزم Nest الثلاث معاً ضمن 11.x، وإعادة تدقيق شجرة `multer`, `path-to-regexp`, و`file-type`، ثم smoke لمسار الصحة والهوية والمؤسسات والتواصل والتحليلات.
3. **دفعة C — P1:** تحديث أدوات التطوير patch/minor بصورة منفصلة، بلا TypeScript 7 أو Node types 26 في هذه الدورة.
4. **بوابة القبول:** لا تعد الدفعة مغلقة إلا إذا نجح `npm audit` وفق عتبة يوافق عليها المجلس، مع صفر critical وصفر high على الأقل في تبعيات الإنتاج.
5. **خطة رجوع:** كل دفعة التزام مستقل؛ الرجوع إلى lockfile السابق إذا فشل البناء أو الاختبار أو تغير سلوك API.

لا يوصى بـ `npm audit fix --force` لأنه قد يغير أجيالاً رئيسية ويخلط إصلاح الأمن بتغيير معماري غير مدروس.

## 16. الخلاصة المرفوعة للمجلس

أنجز الفريق استعادة الاستقرار المحلي ومنع التراجع الحالي، لكن الأمن والنطاق وسلطة البيانات والتشغيل المركزي تمنع وصف المنصة بالجاهزة للإنتاج. الترتيب الصحيح للدورة التالية هو: **اعتماد النطاق، إغلاق المخاطر الأمنية الحرجة والعالية، توحيد سلطة البيانات، ثم القياس**. لا يوصى بأي توسع وظيفي قبل إغلاق هذه البوابات وإعادة حساب نسبة 63% على تعريف MVP مصادق عليه.
