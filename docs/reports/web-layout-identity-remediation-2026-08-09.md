# تقرير معالجة قص الواجهات وتعميم الهوية البصرية

## القرار

عولج السبب الجذري قبل بدء الصورة السادسة: إطارات الهاتف في الصور المرجعية لم تعد حاويات إنتاجية ثابتة. أصبحت الصفحات Web Layout متجاوبة، بينما بقيت الصور مرجعاً للترتيب والهوية فقط.

## التشريح الجذري (Autopsy)

| السبب السابق | الأثر | المعالجة |
| --- | --- | --- |
| عرض 25rem وارتفاع 48/53rem | واجهة تبدو كلقطة هاتف | عرض محتوى حتى 72rem وتدفق طبيعي |
| `overflow:hidden` في shell | قص الشعار والمظلة والنموذج | إزالة القص من حاويات الويب |
| الرسم `absolute` بالكامل | تداخل عند تغير الارتفاع | الرسم قسم مستقل responsive داخل grid |
| padding علوي ثابت | فراغ/قص على الشاشات القصيرة | grid areas ومسافات `clamp()` |
| هوية زرقاء متفرقة | اختلاف التسجيل عن بقية المشروع | tokens موحدة: midnight/navy/green/sky |
| نصوص وأهداف نقر صغيرة | ضعف القراءة واللمس | 12px كحد أدنى للمحتوى التشغيلي و44px للأفعال |

## النطاق المنجز

1. تسجيل الدخول وإنشاء الحساب: عمودان على الشاشات الواسعة، وعمود واحد قابل للتمرير على الهاتف.
2. الرسم والهوية: مساحة مستقلة بنسب مرنة؛ لا يعتمد ترتيبها على ارتفاع لقطة مرجعية.
3. الرئيسية: شبكة خدمات responsive، بحث حقيقي، بطاقة تعريف، وتنقل قانوني بلا إطار جهاز.
4. الترحيب: خريطة وهوية في عمودين على الويب وعمود واحد على الهاتف.
5. الكتالوج: عرض ويب مرن، شبكة نتائج auto-fit، حالات تحميل/خطأ/فراغ، وأهداف لمس 44px.
6. بقية صفحات V1: متغيرات الهوية العامة، navigation، cards، actions، focus، والأسطح أصبحت ضمن النظام الداكن الأخضر نفسه.

## KILLCRITIC

- لم يُكتف بتصغير الشعار؛ لأن ذلك يخفي العرض ولا يصلح القص.
- لم يبدأ تنفيذ الصورة السادسة فوق shell مكسور.
- لم تُعد إضافة إطار هاتف على سطح المكتب.
- لا تعني وحدة الهوية أن جميع صفحات V1 متطابقة؛ القوالب تختلف، لكن tokens والتركيز والسطوح والإجراءات موحدة.
- القبول البصري النهائي يحتاج متصفحاً ولقطات runtime؛ نجاح build والاختبارات لا يثبت وحده المطابقة البصرية.

## بوابة الصفحة السادسة

يمكن تحليل الصورة السادسة بعد معاينة هذه المعالجة. تستخدم الصفحة السادسة القالب المتجاوب نفسه، ولا تنسخ إطار الهاتف أو أبعاد الصورة أو مواضعها المطلقة.
