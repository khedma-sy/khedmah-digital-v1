# معالجة خطأ Binary files are not supported

## السبب

ملف بطل الصفحة الأولى كان WebP ثنائياً. بعض أدوات إنشاء/دمج الرقع لا تنقل binary diffs، حتى لو كان Git نفسه يدعم الملف؛ لذلك ظهر الخطأ عند الدمج.

## الحل المطبق

- حذف WebP الثنائي من `public/brand/`.
- تحويل البايتات نفسها إلى Base64 مقسم إلى أسطر نصية داخل `apps/frontend/lib/brand-hero-image.ts`.
- تصدير Data URL ثابت واستخدامه في `next/image` مع الأبعاد الأصلية و`unoptimized`.
- لم تتغير جودة الصورة أو محتواها؛ تغيرت فقط وسيلة تخزينها ونقلها عبر الرقعة.

## لماذا هذا الحل الآن؟

لا يحتاج Git LFS أو استضافة خارجية أو خدمة بريد أو إعداد deployment إضافي، ويجعل التغيير نصياً قابلاً للدمج في الأداة الحالية. المقابل هو زيادة حجم النص بسبب Base64؛ يمكن نقل الأصل لاحقاً إلى object storage/CDN معتمد عندما تتوفر حوكمة الأصول والبنية المناسبة.

## اختبار القبول

1. لا يبقى ملف PNG/WebP/JPEG جديد في diff.
2. TypeScript يبني Data URL صالحاً يبدأ بـ`data:image/webp;base64,`.
3. `next build` ينجح.
4. اختبارات الصفحة تتحقق من استخدام `KHEDMAH_HERO_IMAGE`.
